# TXV Developer Guide

## Architecture

```
txv-core        Pure logic. Zero I/O. Defines View trait, GroupState, Buffer,
                Event, geometry. No terminal dependency — testable without a TTY.

txv-render      Terminal I/O (crossterm). Implements Backend trait.
                TermBuf: VTE terminal emulator for PTY output.
                Diff flush: only changed cells written to terminal.

txv-widgets     Concrete Views built on txv-core.
                Each widget is a self-contained View implementation.

txv-edit        Vi-style editor: buffer, motions, commands, view, highlighting.

txv-gallery     Demo app + scenario tests using MockBackend.
```

### Dependency Graph

```
txv-gallery → txv-widgets, txv-edit, txv-core
txv-edit    → txv-core
txv-widgets → txv-core, txv-render (for TermBuf/PtyTerminal only)
txv-render  → txv-core (for Backend trait, Buffer, Event)
```

## Key Design Decisions

### Retained Mode (not Immediate Mode)

Unlike ratatui (redraw everything every frame), TXV views own their state and
only redraw when dirty. The framework tracks `needs_redraw()` and the backend
performs diff-flush (only changed cells go to the terminal).

### Composition + Delegation Macros

Views compose ViewState/GroupState as fields, then delegate via macros:
- `delegate_view_state!(field)` — View trait boilerplate for leaf views
- `delegate_group_state!(field)` — Group render + dispatch + View delegation

### Render Pipeline (strict rules)

```
render() [generated by macro]:
  1. For each visible child: child.render() (recursive)
  2. self.draw() — widget fills its own buffer (chrome, background)
  3. Blit all visible children's buffers on top
  4. mark_redrawn()
```

**Absolute rules:**
- `draw()` ONLY called from `render()` — never directly
- `blit_child()` ONLY called from `render()` — it's `#[doc(hidden)]`
- `set_child_bounds()` ONLY from `handle()` or `set_bounds()` — NEVER from `draw()`
- Views draw at (0,0) relative to their own buffer

### Three-Phase Event Dispatch

GroupState dispatches events in order:
1. Preprocess children (e.g., TabBar intercepts Alt-digit)
2. Focused/modal child
3. Postprocess children

### Command-Based Communication

Views never call each other. They emit commands via `state.put_command(id, data)`.
Commands are drained from the EventSink after each event and re-delivered to root.

## Testing

### MockBackend

txv-core provides `MockBackend` for headless testing:

```rust
use txv_core::prelude::*;

#[test]
fn test_view() {
    let mut view = MyView::new();
    let mut backend = MockBackend::new(80, 24);
    view.set_bounds(Rect::new(0, 0, 80, 24));
    run_cycles(&mut view, &mut backend, 1);
    assert!(backend.contains("expected text"));
}
```

### MockBackend API

```rust
backend.inject_key(code, modifiers)  // queue a key event
backend.inject_str("text")           // queue chars
backend.contains("text") -> bool     // check screen content
backend.row(y) -> String             // get a screen row
backend.fg_of(ch) -> Option<Color>   // find color of first occurrence
backend.screen_text() -> String      // full screen dump
```

### Testing Principles

- **Deterministic** — no timing, no shared state
- **Independent** — each test runs in isolation, parallel-safe
- **Use `contains()`** — avoids false positives from status bar clock
- **One file per feature** — test files cover a single concern

### Running Tests

```bash
cargo test --workspace
cargo clippy --all-targets  # zero warnings
```

## Code Standards

### Formatting

- `rustfmt.toml`: `max_width = 120`, `single_line_if_else_max_width = 0`

### Linting

- Zero clippy warnings: `cargo clippy --all-targets`
- MCP lint: `check_file` enforces encapsulation, method length, file length, nesting

### File Size

- **240 code lines maximum per file** (blank/comment lines don't count)
- When exceeded: split by responsibility into separate files
- Never reduce code quality to fit the limit

### Encapsulation

- ViewState/GroupState fields are `pub(crate)` — external crates use accessor methods
- Never access fields through method returns (use accessors): `bar().titles()` not `bar().titles`

## Contributing

### Adding a Widget

1. Create `txv-widgets/src/my_widget.rs`
2. Embed `ViewState` (leaf) or `GroupState` (container)
3. Implement `View` using `delegate_view_state!` or `delegate_group_state!`
4. Re-export from `txv-widgets/src/lib.rs`
5. Add tests, ensure `cargo clippy --all-targets` passes

### Commit Style

- Imperative mood: "Add widget" not "Added widget"
- Prefix: `feat:`, `fix:`, `refactor:`, `docs:`
- Body explains WHY, not just what
- One logical change per commit
